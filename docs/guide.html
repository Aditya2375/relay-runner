TECHNICAL GUIDE / READ THE BOUNDARIES

Know what
you are enabling.

The transport is a narrow task registry. The coding loop is more powerful. Both run as your operating-system user, not in an isolated sandbox.

A / SIGNED TRANSPORT

Named tasks. Checked envelopes.

Each task envelope includes a version, random ID, timestamp, task, arguments and HMAC-SHA256 signature. Modified signatures, stale jobs and replayed IDs are refused. A signature proves possession of a shared key, not that a request is safe or that a sender is honest.

node bin/relay.js init --home ./sandbox
node bin/relay.js issue system.summary --home ./sandbox --out ./sandbox/summary.json
node bin/relay.js run ./sandbox/summary.json --home ./sandbox

Keep the home directory private. The current registry is deliberately small:

TaskEffect
system.summaryReports system and runtime details.
workspace.listLists up to 50 top-level names. Not file contents.
notes.appendAppends up to 500 characters to a fixed notes file.
command.node-versionRuns the fixed Node version command, only with explicit command opt-in.

Loopback listener

node bin/relay.js allow my-agent --home ./sandbox
node bin/relay.js listen --home ./sandbox

In another terminal, send one signed task:

node bin/relay-agent.js system.summary --sender my-agent --key-file ./sandbox/.relay/senders/my-agent.key

The listener binds to 127.0.0.1. It is not a remote endpoint. Other processes on your machine can still attempt to reach it. Each sender gets a key; request decisions are written to .relay/run.log. Do not expose this listener publicly.

B / CODING MODES

Review what the model proposes.

Single-edit mode

node bin/relay.js ai --task "Describe the change" --workspace . --provider gemini

Reads project content, asks a provider for file edits, displays a diff and applies changes only after approval. Gemini, Anthropic and OpenAI-compatible endpoints use the provider layer. Endpoint compatibility does not guarantee every model will produce useful output.

Multi-step agent mode

node bin/relay.js agent --task "Fix the failing test" --workspace . --enable-commands

The model chooses one structured action at a time: read_file, write_file, run_command or done. Results feed back into the next step. Writes and commands ask for approval; a grants that action type for the rest of the run. Commands additionally require --enable-commands.

Unlike the signed transport, this mode can run shell commands. An approved command runs with your privileges. It is not contained by the file-path checks. Review repository code before running its tests or scripts.

Limits: one whole-file write per step, no memory between runs, no parallel steps and no native provider tool-calling. A model can make mistakes, return invalid JSON or exhaust the step cap without finishing. The default cap is 12; change it with --max-steps. Model calls have a 120-second timeout and are not automatically retried.

See the mock-provider loop transcript for an example repair. It is a test fixture, not evidence that a particular hosted model will finish the same task.

C / PASTE BRIDGE

You carry the request.

node bin/relay.js bridge --prompt
node bin/relay.js bridge

Paste the printed connector prompt into a chat service, then paste its JSON reply into the second command. End input with Ctrl-D on macOS/Linux, or Ctrl-Z then Enter in Windows PowerShell. Inspect the job and approve with y.

The bridge signs locally only after your approval. It does not authenticate a web model's identity. It exposes the same four fixed transport tasks, not arbitrary coding work. The chat service cannot reach your machine by itself.

LIMITS / READ BEFORE EXTENDING

A guard is not a sandbox.

  • Signing keys are shared secrets. A process that can read them can impersonate a sender. Filesystem permissions do not isolate processes using the same account.
  • Model snapshots skip common secret files, binaries, .git, .relay and node_modules. This is not complete secret detection. Review the workspace before sharing it with a provider.
  • File actions use path and symlink guards. Shell commands can still reach beyond the workspace. Keep command execution off unless the task needs it.
  • Logs may contain prompts, responses, proposed changes and task details. Protect them as private project data.
  • Replay IDs are reserved before dispatch. If a process crashes after reservation, that job is lost rather than silently repeated.
  • This teaching prototype does not protect against a compromised account, operating system, Node runtime, malicious repository or malicious operator. It has not been independently security-certified.

Before adapting it for real deployment, review OS isolation, authenticated pairing, key rotation, resource limits and per-task consent. Do not accept internet-submitted jobs with this prototype.

ABOUT THE WEBSITE

A port, not a remote control.

The web playground uses WebCrypto and fixture files. It does not connect to your CLI, call a model, or access your real filesystem. Natural-language requests use an offline rule mapper.

The repair example has a scripted planner and automatically approved fixture edits. Its code check actually executes the example in a short-lived browser worker. Those automatic approvals are demonstration behaviour, not the installed agent's default.

Demo notes persist in this browser's local storage until reset or cleared. Do not enter private information. The protocol instrument only lists fixture names; its coloured packets illustrate the route and are not operational telemetry.

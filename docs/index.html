The boundary is the product.

A deliberately narrow loop
Most agent-to-machine ideas start with a command box. This one starts with a question: what should an agent never be able to do?

THE MECHANICS

Small by design.

A working prototype you can read in an afternoon. The first version has four named tasks and zero external dependencies.

01

Signed, then checked

HMAC-SHA256 seals every request. Edited, stale and replayed jobs fail before they can run.

02

Named work only

Get a system summary, list top-level names, or append a note. The agent does not choose a file path.

03

Commands need a key turn

Off by default. Explicit opt-in permits one fixed command template, not a shell prompt.

NOT A REMOTE ACCESS TOOL

Trust is not
a prompt setting.

Point an AI at an unrestricted command runner and you have built a command-and-control channel. A compromised agent could read private files or run anything it wants.

Relay Runner has no remote listener. Jobs need a valid local signature, expire after two minutes, and can run only registered tasks. Commands are off unless the operator opts in, and even then the example can only print the Node version.

Prototype, not a sandbox. A program running as your OS user can read the shared key. Do not connect this demo to an untrusted remote agent. Read the threat model before extending it.

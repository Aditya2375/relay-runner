A deliberately narrow loop
Most agent-to-machine ideas start with a command box. This one starts with a question: what should an agent never be able to do?

THE MECHANICS

Small by design.

A working prototype you can read in an afternoon. The first version has four named tasks and zero external dependencies.

01

Signed, then checked

HMAC-SHA256 seals every request. Edited, stale and replayed jobs fail before they can run.

02

Named work only

Get a system summary, list top-level names, or append a note. The agent does not choose a file path.

03

Commands need a key turn

Off by default. Explicit opt-in permits one fixed command template, not a shell prompt.

AGENT MODE / BRING ANY MODEL

Any AI model you want.
Your key, your machine.

Agent mode plans, acts and checks step by step with whatever model you point it at: a free Gemini key, Claude, GPT, or a fully local model. It is the open, local-first way to get what closed agent tools do - every step still asks your approval before anything runs, and your key is read from your environment, never stored.

01

Gemini - the free path

Default provider. A key from AI Studio's free tier costs nothing and is what the recordings use. Set RELAY_GEMINI_KEY and go.

02

Claude

Set RELAY_ANTHROPIC_KEY and run with --provider anthropic. Pay-per-token - Anthropic has no free tier, so this path costs money.

03

OpenAI-compatible - everything else

RELAY_OPENAI_KEY plus an optional RELAY_OPENAI_BASE_URL reaches OpenAI, OpenRouter or Groq - and a local Ollama at localhost:11434 needs no key and sends nothing out.

Honest limits: the loop speaks strict JSON over plain completions, so weak models can fumble and burn the step cap; free-tier Gemini flash or a decent local model is the sweet spot. Whole-file writes, one file per step, no memory between runs.

WORKS WITH ANY CHAT AI

Type it in ChatGPT, Claude
or Gemini. It happens here.

Paste the connector prompt (node bin/relay.js bridge --prompt) into any chat AI. It answers with one small JSON job. Paste that into node bin/relay.js bridge, read exactly what the AI asked for, and type y - only then is it signed and run, on your machine, inside the rules above.

01

You are the transport

A web AI cannot reach your machine. The paste is the wire - which also means nothing runs unless you carry it and approve it.

02

Approval is the verification

The AI never sees your key. The local signature attests your y at your keyboard, not the AI's identity - the “checks who asked” promise stays true.

03

Small jobs, honestly

The bridge runs the same four registered tasks as the listener - nothing free-form. For open-ended work, agent mode in the terminal drives any model with your own key.

NOT A REMOTE ACCESS TOOL

Trust is not
a prompt setting.

Point an AI at an unrestricted command runner and you have built a command-and-control channel. A compromised agent could read private files or run anything it wants.

Relay Runner has no remote listener. Jobs need a valid local signature, expire after two minutes, and can run only registered tasks. Commands are off unless the operator opts in, and even then the example can only print the Node version.

Prototype, not a sandbox. A program running as your OS user can read the shared key. Do not connect this demo to an untrusted remote agent. Read the threat model before extending it.
